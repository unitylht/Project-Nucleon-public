# Doctor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Owner picks one of six questions about how their setup is working and gets counts, a suggested change and its cost, all worked out by code from their own cases; the Owner's chat assistant can read the same facts through one new read-only tool.

**Architecture:** A new pure module `prototype/doctor.py` answers the questions from case dicts and a policy. One read-only endpoint serves a page (`prototype/web/doctor.js`) and one Owner tool (`doctor`) serves the chat assistant; both return the same code-written lines. Suggestions are Quick setup answers, opened in Quick setup unsaved.

**Tech Stack:** Python 3 standard library, `unittest`, plain JavaScript pages, headless-Chrome page checks, the Lab's MCP server, a mongosh script for the LibreChat agent.

**Spec:** `docs/superpowers/specs/2026-11-11-doctor-design.md`

## Review Focus

1. A workspace with no cases at all, or none in the window: every question answers with zero counts and a "too few" note; nothing divides by zero.
2. Cases recorded before a setting existed (no `daysFromRequest` / `daysPastOriginalDue` feature, no `receivedDate`, no `evaluation.features`): skipped or judged "not applicable", never a crash, and the note says how many were left out.
3. A what-if that would have approved cases the Owner declined: the cost is in the sentence, and such a suggestion is never listed first.
4. Trial-credit cases: counted in questions 3 and 5, left out of what-ifs (Quick setup does not cover them), and the note says so.
5. The `try` parameter on Quick setup with broken or hostile JSON (not an object, unknown keys, script text): ignored or escaped, the page still loads, nothing is saved.

**Interfaces:**
- Produces:
  - `QUESTIONS = (('came', 'Why do so many requests still come to me?'), ('corrections', 'Why do I keep correcting the agent?'), ('help', 'How much is the agent helping?'), ('outcomes', 'Did the extensions the agent approved get paid?'), ('customers', 'Which customers come to me most?'), ('rules', 'Which rules never matter, and which block everything?'))`
  - `MIN_CASES = 5`, `DAY_STEPS = (45, 60, 90, 120, 180, 365)`, `MAX_COMBINED = 3`
  - `in_window(cases, as_of: date, days: int | None) -> list` (by the date part of `createdAt`; `None` = all)
  - `reasons_of(case) -> [(key, label)]`: the checks with status `fail` or `unknown` in `case['evaluation']['risk']['checks']`; when the first routing was `policy_hold` and `evaluation.features.heldCustomer` is true, `('held_customer', 'The customer is on your never-decide list')` first; when nothing else, `('other', evaluation['why'] or 'Another rule')`.
  - `answer(question: str, cases: list, policy: dict, settings: dict, as_of: date, days: int | None, names: dict, events_by_case: dict = None, preview=None, preview_for=None) -> dict` with the shape below. `preview` is `{'total': int, 'counts': {...}, 'reasons': [...]}` for the current policy; `preview_for(answers_patch) -> same shape` is a callable the server supplies; both may be `None` (then no look-ahead lines).
  - `headlines(...same arguments without question...) -> [{'question', 'label', 'headline'}]`

Answer shape (all text written by code):

```python
{'question': 'came', 'label': 'Why do so many requests still come to me?',
 'window': {'days': 30, 'cases': 41},
 'enough': True,                       # False when the finding rests on fewer than MIN_CASES
 'headline': '20 of your 41 requests came to you. The most common reason: the customer had another overdue invoice (11).',
 'findings': ['11 because ...: you approved 9, declined 1, 1 is still waiting.', ...],
 'suggestions': [{'text': 'If ...: the agent would have decided 9 of these 20 itself (now 0). You had approved 9 of those 9 and declined 0.', 'answers': {'allowOtherOverdue': True}}, ...],
 'notes': ['What-ifs judge the limits only, on the facts recorded when each case was decided.', ...],
 'facts': [...]}                       # headline + findings + suggestion texts + notes, in that order: what the tool hands the assistant
```

Rules that decide the numbers:

- **First routing** of a case: `case['evaluation']['handling']`. "Came to the Owner" = `owner_review` or `policy_hold`. Verify on a real resolved case in Step 1 that this field keeps its value after the Owner decides; if it does not, use the first entry of `case['history']` and ledger the ruling.
- **What the Owner did**: `impact.owner_decided(case)` → `decision.outcome` (`approve` / `decline`); otherwise `waiting`.
- **A what-if on a past case** = `delegation.would_approve(candidate, 'extension', case['evaluation']['features'])`, where `candidate = delegation.validate_policy(delegation.quick_setup_policy({**delegation.quick_setup_answers(policy), **patch}, policy), settings)`. Only extension cases that have `evaluation.features` are tried; the others are counted in a note.
- **Relaxations for `came`** (each a Quick setup answers patch; offered only when it differs from the current answers):
  - `other_overdue`: `{'allowOtherOverdue': True}`; label "customers with another overdue invoice were allowed".
  - `late_history`: `{'lateHistory': 'any'}`; label "customers who paid late before were allowed".
  - `total_days`: `{'daysPastOriginalDue': n}` for each `n` in `DAY_STEPS` above the current value; keep the smallest `n` that reaches the largest gain; label "the total-lateness limit were n days".
  - `from_request`: `{'daysFromRequest': None}` when one is set; label "there were no limit counted from the day of the request".
  - `invoice_limit`: `{'maxInvoice': plain}` with the largest `exposure` among the cases failing `decision_exposure`; label "the invoice limit were <money>".
  - `customer_limit`: the same from `customerExposure` and `customer_exposure`.
- **Combination**: greedy. Start from no change; up to `MAX_COMBINED` times add the relaxation that makes the agent decide the most additional cases; stop when none adds any. Report the combination only when it has two or more parts and beats the best single change.
- **Order of suggestions**: by gain, largest first; among equal gains the one with fewer Owner-declined cases first. A suggestion whose decided cases include more Owner-declined than Owner-approved is put last and its text ends "You declined most of these, so this change is not recommended."
- **Suggestion sentence for `came`** (exact): `"If {label}: the agent would have decided {k} of these {n} itself (now {k0}). You had approved {a} of those {k} and declined {d}."` followed, when `preview_for` is given, by `" On today's open invoices it would decide {p1} of {t} (now {p0})."`
- **`corrections`**: among the agent's decided cases in the window, `reviewed` = overridden or with a last verdict; `corrected` = `impact.overridden(c)` or `impact.last_verdict(c) == 'disagree'`; `agreed` = last verdict `agree` or `tacit_agree`. Agent declines that were corrected are counted in one finding and not searched. For the corrected approvals, try tightenings and keep, per dimension, the candidate with the largest `caught_corrected − caught_agreed` (ties: fewer agreed caught); list those with `caught_corrected >= 2` and `caught_corrected > caught_agreed`:
  - total days: for each distinct `daysPastOriginalDue` (else `extensionDays`) `v` among the corrected, patch `{'daysPastOriginalDue': v - 1}` when `v - 1 >= 1`;
  - invoice amount: for each distinct `exposure` `v`, patch `{'maxInvoice': plain(v - 1)}`;
  - customer total: the same with `customerExposure` and `maxCustomer`;
  - late history: `{'lateHistory': 'some'}` and `{'lateHistory': 'none'}` when stricter than now;
  - other overdue: `{'allowOtherOverdue': False}` when it is allowed now.
  A case is "caught" when `would_approve(candidate, ...)` is false.
  Sentence (exact): `"If {label}: {c} of the {C} approvals you corrected would have come to you instead (now 0), and so would {a} of the {A} you agreed with."`
- **`help`**: counts in the window: all requests; the agent approved / declined; came to the Owner; held; still gathering information; of the agent's decisions: reviewed, agreed, corrected, not reviewed yet.
- **`outcomes`**: the agent's approvals that still stand (`impact.observable`), by `impact.observation(case, events)`; labels: `on_time` "paid by the new date", `late_paid` "paid late", `partial` "part paid", `open_not_due` "not due yet", `open_past_due` "past the new date and unpaid", `written_off` "written off", `unknown`/None "not known yet".
- **`customers`**: the five customers with the most cases that came to the Owner (ties by name), each with its count, its total requests and its most common reason; names from `names`.
- **`rules`**: for each check key seen in the window's cases or in `preview['reasons']`: how many real requests it sent to the Owner, and how many of today's open invoices it blocks. "Blocks almost everything" when it blocks at least 90% of `preview['total']` and `preview['total'] >= MIN_CASES`. "Never mattered" for the keys in `delegation.QUICK_CHECK` that appear in neither, when the window has at least `MIN_CASES` cases.
