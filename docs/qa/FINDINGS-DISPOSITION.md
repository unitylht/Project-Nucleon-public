## Other observations in the report (not findings)

- **Preparing timer.** It counts from the start of the active run. It now reads "N s so far", and the hint says the page can be left while the case is prepared.
- **Overdue "Unknown" with a due date.** Intended. Days overdue are calculated only when an amount still owed is known; the case says why.
- **Technical details visible to staff and the owner.** Kept, under a "Technical" tab. Runs are now listed in time order.
- **Elements measured beyond the right edge on the narrow home page.** The page structure was replaced. `ui_check` and `layout_check` find nothing outside the width at 375, 390, 820 and 1366 px.
- **Approval did not change the invoice's due date in Records.** Intended: the record keeps its original due date. The customer's invoice list now shows "Extended to … by an approved request" under Due.

## Found during this work (not in the report)

- **The skip link changed the route.** The new "Skip to content" link was a `#main` hash link, which the hash router treated as a page change. Fixed before commit; `ui_check` B13.
- **Agent status took 30 s to appear.** After sign-in, the header said "Checking the agent" for up to 30 s. Fixed in `4fa5726`; `browser_check` live.
- **The Stage 3 smoke check could not run twice on one database.** It used a fixed customer name. It now labels each run.
- **A revert that removes only an import's bookkeeping still flags decided cases.** Deferred at `810a4cc`; fixed after the review, with a migration: see R4 below.
  - The decision-evidence key fingerprints the whole invoice record, including which imports also listed it. So reverting a zero-row import flags decided cases "records changed", with the same amount before and after.
  - Changing the key needed a migration, documented before it was implemented: [../EVIDENCE-KEYS.md](../EVIDENCE-KEYS.md).
