2. Northside Cafe: approved by the agent

Browser A · new ADA chat
Northside Cafe is a new customer and wants AUD 800 of stock on 14-day terms; they paid a deposit.
  1. Send it. The agent finds Northside in Nucleon's records, then asks Nucleon to check the request against the policy.
  2. Scroll to the decision card and read it from the top.
Expect: Approved under policy version 1. Order $800 − verified deposit $200 (reference DEP-NS-01) = $600 exposure, within the $600 new-customer limit. Every limit it was checked against is listed below. The card arrives in about 10–20 s, the full reply in 30–60 s.

Point to make: Nucleon sends nothing to the customer; Staff tell them. A new customer is no longer another phone call to the owner. An early "Would be decided" preview card is not the decision; wait for the final card.

3. Harbourline Catering: too big, goes to the owner

Browser A · new ADA chat
Harbourline Catering, a new customer, wants AUD 5,000 on 14-day terms with a deposit.
Expect: sent to the Owner, nothing approved. Order $5,000 − deposit $1,000 = $4,000 exposure, over the $1,000 limit for one decision.

Then show it waiting

  1. Browser B: reload the Owner page. Harbourline is under the waiting cases with Needs your decision, a reason box, and Approve / Decline.

Point to make: Nucleon's own system holds the agent to the limit, whatever the AI says. In the video we only showed it waiting; deciding it is optional, and it changes the data until the next reset.

5. What the owner sees afterwards

Browser B · Owner page
  1. Reload the Owner page and scroll down slowly.
  2. Waiting: Harbourline, needs your decision.
  3. Decided by the agent: Northside and Lakeside, each with Agree / Disagree / Override.
  4. Suggestions: changes to the policy based on reviewed cases (suggestions only).

Point to make: the owner monitors and acts when they see fit. Over time, as more decisions are recorded and checked, they can hand over more, one policy version at a time. The track-record check uses made-up past cases for this demo, so it is a simulation.

6. Afterwards

This Mac

Put the demo back to clean data (keeps a backup of the current data first):

~/Developer/nucleon-local/bin/demo-reset

If something goes wrong

  • Agent loops or repeats tool calls: Qwen's context is probably not 32768. Run demo-reset and follow its warning line.
  • Card button opens a Nucleon login page: Browser A is not signed in to Nucleon as Staff. Sign in, then click the button again.
  • A case says it was already handled: it was run before this reset. Reset, save version 1 again, and rerun.
  • Agent asks a question instead of deciding: answer it or rerun with the exact prompt above; it asks rather than guessing on vague requests.

Prompts and values match the video's recording script (record_v2.py). Expected numbers come from that recording's backend records.
